# Task-Closure Memory v2: paired 30-task probe

This directory preserves the complete first run of Task-Closure Memory v2 on a fixed
10-task subset from each STATE-Bench domain. It is a local diagnostic probe, not a
protocol-compliant leaderboard result: only one run and 10 tasks per domain were used.

## Result

The comparison uses the exact same task IDs from the archived cross-domain PWM run1.

| Domain | Method overall | PWM overall | Method state | PWM state | Method task | PWM task |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Travel | 6/10 | 4/10 | 7/10 | 6/10 | 6/10 | 4/10 |
| Customer Support | 4/10 | 5/10 | 7/10 | 7/10 | 5/10 | 6/10 |
| Shopping Assistant | 4/10 | 3/10 | 10/10 | 10/10 | 4/10 | 3/10 |
| Total | **14/30** | **12/30** | **24/30** | **23/30** | **15/30** | **13/30** |

There were four gains and two regressions:

- Gains: Travel 9, Travel 23, Travel 33, Shopping 7.
- Regressions: Travel 30, Customer Support 34.

The discordant count is only six tasks (4 vs. 2), and the baseline came from an earlier
single run rather than a concurrent rerun. The +2 result is therefore descriptive and
must not be treated as a causal improvement or SOTA evidence.

## Efficiency

| Metric | Method | PWM | Delta |
| --- | ---: | ---: | ---: |
| Mean tokens/task | 158,360 | 43,112 | +115,248 |
| Mean turns/task | 2.93 | 3.33 | -0.40 |
| Mean tool calls/task | 9.40 | 8.10 | +1.30 |
| Mean UX | 3.922 | 3.678 | +0.244 |

The semantic bookkeeper used 3,411,015 tokens over 269 calls. It accounts for about
71.8% of all method tokens and is the main source of the 3.67x total-token multiplier.

## Configuration

- Code: `codex/task-closure-memory-v2` at `99f9bfcefa0f84be20435d4da536117688c0b4fe`.
- Frozen PWM source: `archive/statebench-cross-domain-pwm` at `152bf48`.
- STATE-Bench: 0.8.1, upstream commit `5644b1838d96bc4483da29642d058ecaa6f80f7f`.
- Agent/model: `TaskClosureMemoryAgent`, `gpt-5.4`.
- Procedure Memory: hybrid, top-k 3.
- Completion Memory: full, independently retrieved top-k 8.
- Runs/workers: one run, one worker per domain; the three domains ran concurrently.
- Scoring: inline State, Task Requirements, and UX with high judge reasoning effort.
- Provider URL and credentials are intentionally excluded.

The exact task list and immutable hashes are in `manifest.json` and `RAW_SHA256SUMS`.

## Files

- `*/run1/*.json`: 30 scored trajectories with Completion Memory diagnostics.
- `*/per_task_metrics/*.json`: local per-task metrics generated by STATE-Bench.
- `*/metrics.json`: local subset summaries generated with `--ignore-missing-runs`.
- `*.log`: complete worker logs.
- `paired_summary.json`: machine-readable paired comparison and mechanism statistics.
- `manifest.json`: experiment identity, configuration, task list, and provenance.

The `metrics.json` files retain STATE-Bench's standardized schema, but they cover only
the selected 10 tasks. They are not full-split or five-run metrics.

## Reproduce the local subset summary

Use the task IDs in `manifest.json`, run with the configuration above, and compare the
resulting `run1` files to:

```text
artifacts/statebench_cross_domain_pwm/runs/<domain>/run1
```

The complete mechanism audit is in `../../AUDIT.md`.
